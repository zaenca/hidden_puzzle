# Процедурные комнаты

Интерьер собирается из трёх поверхностей вместо одного нарисованного фона.
Смысл — чтобы новая локация стоила **один JSON**, а не заказ цельной картинки
комнаты. Материалы, окна, двери и грязь комбинируются, и из одного набора PNG
получается сколько угодно непохожих помещений.

Система **не заменяет** существующие фоны. Локация без поля `room` работает
ровно как раньше: `background` → картинка, пусто → градиент. Переход идёт по
одной комнате за раз.

---

## Как это устроено

```
RoomTemplate      геометрия: размеры коробки + камера        content/room_templates.json
RoomMaterial      текстура + размер плитки в единицах комнаты content/room_materials.json
RoomDefinition    что где стоит в конкретной комнате          content/rooms/<id>.json
      │
RoomGeometry      проецирует коробку в экранные полигоны      core/room/room_geometry.gd
RoomHomography    отображение «поверхность ↔ экран»           core/room/room_homography.gd
RoomTextures      процедурные заглушки, пока нет PNG          core/room/room_textures.gd
RoomAssembler     собирает ноды                               core/room/room_assembler.gd
      │
ShopScene         ставит комнату вместо фона локации          meta/shop/shop_scene.gd
```

### Почему так, а не Polygon2D с UV

Godot режет полигон на треугольники и интерполирует UV **аффинно**. На трапеции
пола это даёт классический излом текстуры по диагонали: плитка у дальнего края
не уменьшается, а ломается.

Поэтому координата поверхности считается **в шейдере, из позиции пикселя**,
обратной гомографией: `uv = (H⁻¹ · [x, y, 1])` с делением на однородную
координату. Это перспективно корректно по построению и не зависит от того, как
полигон стриангулировался.

Следствия, которые важнее самой формулы:

- **Одна поверхность — один Polygon2D.** Пол из 150 плиток — это один объект
  отрисовки, а не 150 спрайтов. На всю комнату прототипа уходит ~15 нод.
- **Полигон отвязан от отображения.** Рисовать можно любую фигуру: пол —
  пятиугольник до низа экрана, стена — достроенная вверх и вбок трапеция.
  Раскладка плитки при этом та же.
- **Окна и двери — та же гомография.** Дверь у края комнаты сужается вместе со
  стеной, а не выглядит наклейкой поверх неё.

### Геометрия — маленькая камера-обскура

Восемь точек коробки проецируются на CPU один раз при сборке. Это **не 3D**: ни
одной 3D-ноды, ни 3D-рендера. Зато перспектива стен, пола, окна и двери приходит
из одной модели и не может разъехаться между собой.

Наклона у камеры нет намеренно: вертикали комнаты остаются вертикалями на
экране. С наклоном дверь и окно перестают быть вертикальными, и кадр читается
как 3D-скриншот, а не как нарисованная сцена. Горизонт двигается параметром
`horizon`, а не наклоном.

### Координаты поверхности

`rect` элементов и наклеек нормализован **к поверхности**, не к экрану.

```
левая стена            правая стена              пол
u: 0 = дальний край    u: 0 = угол комнаты       u: вдоль правой стены
   1 = угол комнаты       1 = дальний край       v: вдоль левой стены
v: 0 = верх, 1 = пол   v: 0 = верх, 1 = пол      (0,0) = угол, дальняя точка
```

У обеих стен `u` растёт слева направо по экрану — иначе окно на левой стене
пришлось бы размечать задом наперёд.

## Как сделать новую комнату

### 1. Файл комнаты

`content/rooms/my_room.json`:

```json
{
  "id": "my_room",
  "room_template": "medium_room",
  "seed": 1204,

  "surfaces": {
    "left_wall":  { "material": "brick_wall_01" },
    "right_wall": { "material": "white_plaster_01", "tint": "#e8ddc8" },
    "floor":      { "material": "wood_floor_01", "tile_scale": 1.2 }
  },

  "elements": [
    {
      "id": "window_01",
      "type": "window",
      "surface": "left_wall",
      "rect": [0.20, 0.20, 0.30, 0.34],
      "material": "window_wood_01",
      "shadow": 0.10, "inset": 0.55, "frame": 0.055,
      "frame_material": "trim_wood_01"
    }
  ],

  "decals": [
    { "surface": "right_wall", "material": "crack_01",
      "rect": [0.10, 0.28, 0.16, 0.34], "rotation": -7, "opacity": 0.85 }
  ],

  "trims": {
    "corner_shadow":  { "width": 0.12, "strength": 0.42 },
    "baseboard":      { "height": 0.055, "material": "trim_wood_01" },
    "contact_shadow": { "size": 0.10, "strength": 0.38 }
  },

  "vignette": { "strength": 0.22 }
}
```

### 2. Подключить к локации

В `content/shops/my_shop.json` вместо `background`:

```json
"room": "my_room"
```

Всё остальное в локации — слоты, задачи, подсветка, тап — работает поверх
комнаты без изменений.

### 3. Проверить

```bash
godot --headless --path . --script res://tools/validate_content.gd
```

```bash
godot --path . -- --room-shot=my_shop
```

Второй снимает кадр в `room_shot_my_shop.png`. Геометрию принимают глазами, и
делать это через меню на каждую попытку значит не делать вовсе. Шаблон можно
переопределить, не трогая контент:

```bash
godot --path . -- --room-shot=my_shop --room-template=narrow_room
```

В самой игре: `⚙` → «Комната: тест материалов» — стенд с переключателем
шаблона и материалов трёх поверхностей. Включается полем `"debug_panel": true`
в комнате.

## Справочник полей

### surfaces.\<left_wall|right_wall|floor\>

| Поле | Смысл |
|---|---|
| `material` | id из `room_materials.json` |
| `texture` / `generator` | прямой путь или заглушка мимо библиотеки |
| `tile_size` | размер плитки **в единицах комнаты**; ноль — из материала |
| `repeat` | явное число повторов; главнее `tile_size` |
| `tile_scale` | множитель к размеру плитки |
| `tint` | подкрасить |
| `uv_offset` | сдвиг раскладки в долях плитки, чтобы шов не пришёлся в угол |

### elements[] и decals[]

| Поле | Смысл |
|---|---|
| `id`, `type`, `surface` | `type` — window / door / arch / niche / shelf / decal / trim |
| `rect` | `[x, y, w, h]` в координатах поверхности |
| `material` / `texture` / `generator` | чем рисовать |
| `tint`, `opacity` | цвет и прозрачность |
| `rotation`, `flip_h`, `flip_v` | поворот **в плоскости стены**, не на экране |
| `layer` | порядок слоя (пол 0, стены 20, наклейки 30, стыки 40, проёмы 50) |
| `shadow`, `shadow_offset`, `shadow_color` | мягкая тень вокруг проёма |
| `inset` | внутренняя тень откоса, 0..1 |
| `frame`, `frame_material` | наличник |
| `visible_if_flag` / `hidden_if_flag` | видимость по флагу мира |
| `slot` + `slot_state` | видимость по состоянию слота локации |

### trims

`corner_shadow {width, strength}` · `baseboard {height, material, tint}` ·
`contact_shadow {size, strength}`. Всё выключается нулём.

### scatter[]

Процедурный слой **поверх** явной конфигурации, а не вместо неё:

```json
{ "surface": "floor", "material": "stain_01", "count": 4,
  "area": [0.05, 0.05, 0.85, 0.75], "size": [0.08, 0.16],
  "rotation": [-25, 25], "opacity": [0.18, 0.4] }
```

Раскладка детерминирована по `seed` комнаты. Комната со `scatter` и нулевым
зерном — предупреждение валидатора: после перезагрузки она выглядела бы иначе, а
это баг, а не разнообразие.

## Связь с состоянием мира и сейвом

Комната ничего не сохраняет. В сейв идут те же данные, что и раньше: флаги и
состояния слотов. Вид восстанавливается из конфигурации плюс состояния игрока.

Дверь описывается **двумя элементами** с одним `rect` и разными `slot_state`, а
нажатие и смена состояния остаются на существующей системе слотов —
второй системы взаимодействий у комнат нет:

```json
{ "id": "door_01",      "slot": "lab_door", "slot_state": "closed", ... }
{ "id": "door_01_open", "slot": "lab_door", "slot_state": "open",   ... }
```

Слот берёт свою область у нарисованного элемента:

```json
{ "id": "lab_door", "room_element": "door_01", ... }
```

Подогнанный руками `rect` при первой же смене шаблона геометрии уезжает с двери,
и обнаруживается это уже пальцем.

## Какие PNG понадобятся

Пока файлов нет, всё рисуется процедурными заглушками (`generator` в материале).
Появился PNG — в материале заполняется `texture`, и генератор молча перестаёт
использоваться. **Ни один скрипт при этом не трогается.**

### `art/room_materials/` — поверхности

Требования: **бесшовные** (стыкуются сами с собой), сторона — степень двойки
(512×512 или 1024×1024), при импорте **Mipmaps: On**. Без мип-мап у дальнего
края пола начинается муар: там одна плитка занимает считанные пиксели.

| Файл | Заменит генератор |
|---|---|
| `plaster_01.png`, `plaster_02.png`, `plaster_white.png` | `plaster` |
| `brick_01.png` | `brick` |
| `wall_tiles_white.png` | `tiles` |
| `wood_wall_01.png` | `wood` |
| `concrete_01.png` | `concrete` |
| `floor_terracotta_01.png` | `tiles` |
| `floor_wood_boards_01.png` | `wood` |
| `floor_concrete_01.png` | `concrete` |
| `floor_stone_01.png` | `brick` |

### `art/room_elements/` — врезки и грязь

Требования: **с альфой**, нарисованы **в лоб**, без собственной перспективы и без
теней по краям — перспективу и тень накладывает система.

```
windows/   window_wood_01.png, window_arched_01.png, window_shuttered_01.png
doors/     door_old_01.png, door_panel_01.png, door_metal_01.png
trims/     baseboard_wood_01.png, casing_wood_01.png
decals/    crack_01..03.png, stain_01..03.png, cobweb_01.png,
           moisture_01.png, peeling_paint_01.png, scratches_01.png
```

Размер плитки задан **в единицах комнаты**, поэтому замена PNG 256×256 на
1024×1024 ничего в кадре не двигает — меняется только чёткость.

## Ограничения

| Ограничение | Комментарий |
|---|---|
| Комната строится под 1080×1920 | как и весь остальной UI проекта; при другом формате экран масштабируется движком |
| Камера без наклона | сознательно: вертикали остаются вертикалями |
| Потолка нет | стены достраиваются вверх; верх кадра — всегда стена |
| Направленного света нет | есть общий `tint` и виньетка; свет из окна на пол не падает |
| Комната пока только в локации | в уровень (`SceneArt`) не встроена: пазл режет текстуру, а комната — дерево нод |
| Подсветка слота — прямоугольник | рамка «сюда можно нажать» не следует перспективе элемента |
| Заглушки рисуются по пикселям | ~0.3 c на первый вход; кэшируются на весь запуск, с настоящими PNG исчезнет |
