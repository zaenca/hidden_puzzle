Гибрид puzzle + hidden object. Vertical slice: пекарня, уровни 1–5.
Архитектура: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)

**Обновлено:** 2026-08-24
**Текущий этап:** M1 завершён (полный цикл работает и проверяется автоматически)

## Как запустить

Движок в проекте не лежит. Локально проверено на **Godot 4.6.2 stable**
(`C:\Users\leo24\Downloads\godot46\Godot_v4.6.2-stable_win64.exe`).

Игра:

```bash
godot --path . 
```

Автопрогон всего слайса без участия игрока (headless, ~25 c):

```bash
godot --headless --path . --autoplay
```

Отчёт пишется построчно в `autoplay_report.txt` в корне проекта.

Валидатор контента:

```bash
godot --headless --path . --script res://tools/validate_content.gd
```

Первый запуск на новой машине требует импорта: `godot --headless --path . --import`.

**В игре:** `⚙` в правом верхнем углу — debug-панель (сброс прогресса, +гемы,
+бустеры, перемотка времени на 10 минут). Внутри уровня: `S` — собрать пазл,
`F` — найти все предметы.

## Что уже работает

### Полный цикл (проверяется автоматически, 37 проверок)

```
карта района → уровень 1 → jigsaw → бесшовное раскрытие → hidden object
  → сюжетный предмет «План района» → мета: пекарня выбрана
  → пекарня → уровень 2 → метла и мешок → мусор у входа исчез
  → уровни 3–4 (одна задача, две части) → вывеска установлена
  → cooldown ремонта замка (10 мин) + параллельная задача
  → уровень 5 → cooldown сокращён на 3 минуты → витрина и ручка
  → mock-ускорение за 25 гемов → дверь открыта
  → сохранение → перезагрузка → все состояния на месте
```

## Ключевые технические решения этого этапа

**Части пазла генерируются кодом.** `JigsawGeometry` строит сетку замков
(Catmull-Rom по профилю), `Polygon2D` берёт UV с общей текстуры фона.
Соседние части используют один массив точек общей грани, поэтому замки всегда
совпадают. Стоимость производства пазла для нового уровня — ноль.

**Бесшовность настоящая, а не имитация.** Фон, слои и цели живут в `SceneView`
с самого начала. Пазл рисуется поверх, фон приглушён. При решении: гаснут швы →
гаснет слой пазла → под ним пиксель-в-пиксель то же изображение → лёгкий
push-in камеры → цели активны. Смены сцены нет.

**Предметы запечены в фон.** `PlaceholderArt` рисует цели прямо в изображение
уровня — так же, как это будет с финальным PNG. Поиск идёт по цвету и форме,
которые продублированы в панели искомых предметов, а не по невидимым хитбоксам.

**Контент — JSON, сейв — JSON, runtime-контракт — типизированные Resource.**
Отклонение от плана (там были `.tres`): вложенные sub_resource неудобно писать
и мержить вне редактора. Классы остались `Resource` с `@export`, поэтому
переход на `.tres` затронет только `ContentDB`.

**Core физически не знает мету.** В `res://core/**` нет ни одного обращения к
`PlayerState`, `MetaService`, `CooldownService` и ни одного упоминания пекарни.
Уровень получает `LevelContext`, отдаёт `LevelResult`.

## Что решено по вопросам из плана

1. Провала уровня нет, таймера нет, lives нет — согласовано.
2. Повтор пройденных уровней разрешён: награда × 0.3, сюжетные предметы
   повторно **не** выдаются (`MetaService.apply_level_result`).
3. Первый cooldown перенесён в слайс: после уровня 4 запускается ремонт замка
   входной двери (10 мин), уровень 5 идёт параллельно и сокращает ожидание на
   3 минуты; мгновенное завершение — 25 mock-гемов, реклама — −2 минуты.
4. Финального арта нет — весь визуал генерируется процедурно.

## Текущие ограничения

| Ограничение | Комментарий |
|---|---|
| Godot 4.6.2, а не 4.7.2 | 4.7.2 не установлен. Проверено на 4.6.2; для перехода поменять `config/features` в `project.godot` на `"4.7"` |
| Весь арт — placeholder | цветные формы и градиенты; финальный PNG подключается через `art.background` в JSON |
| Камера в уровне зафиксирована | pan/zoom и pinch в HO-фазе не реализованы (`allow_zoom` в данных уже есть) |
| Нет mid-level resume | выход из уровня теряет прогресс уровня; контракт `PuzzleModule.serialize_state()` под это уже заложен |
| Нет разметчика целей | цели пишутся руками в JSON; `tools/ho_marker_tool` — следующий шаг (M6) |
| Один puzzle-модуль | jigsaw; реестр `PuzzleRegistry` готов принять screws/bubbles |
| Один бустер | универсальный: в jigsaw ставит часть, в HO подсвечивает предмет |
| Safe area не проверена на устройстве | код есть (`ui/safe_area.gd`), на десктопе отступы нулевые |
| Нет Android-сборки | export-пресет не настроен (M7) |
| `boot_log.txt` / `autoplay_report.txt` | отладочные файлы в корне, пишутся только из dev-запуска |
| Миграций сейва пока нет | версия 1, каркас `SaveService.MIGRATIONS` пустой |
| Звука нет | сознательно вне слайса |

### M1 — Полный цикл · ✅

- бесшовный reveal;
- hidden object с полигональными целями и выдачей сюжетных предметов;

Дополнительно (обгоняя план, потому что без этого нельзя было проверять):
data-driven контент (изначально M2), сохранение (M3), мета-слой (M4),
cooldown (M5) — в минимальном объёме.

**Проверка:**

| Прогон | Результат |
|---|---|
| `--headless --autoplay` | 37 проверок, провалено 0, exit 0 |
| `--autoplay` в окне (реальный OpenGL) | тот же результат, exit 0 |
| `--quit-after 600` в окне (просто постоять на карте) | ни одной ошибки в логе |
| `validate_content.gd` | 0 ошибок, 0 предупреждений |

**Два оставшихся warning'а (оба ожидаемые, не баги):**

- `во время cooldown из активностей остался только повтор уровней` — срабатывает
  в самом конце слайса, когда все пять задач закрыты, а последний cooldown ещё
  идёт. Это не дефект кода, а граница контента: новых задач за уровнем 5 пока
  нет. Инвариант специально отличает «остался только повтор» от «нечем заняться
  совсем» — второе было бы настоящей ошибкой.
- `RIDs / ObjectDB leaked at exit` — **открытый вопрос, причина не установлена.**
  Наблюдения: при запуске, где игрок только постоял на карте (`--quit-after 600`),
  предупреждения нет; после прохождения уровней оно есть — и при выходе через
  `SceneTree.quit()` в автопрогоне, и при обычном закрытии окна (11 и 14
  CanvasItem соответственно). То есть течёт что-то на пути уровня, а не артефакт
  порядка выключения теста. Подозрения (не проверены): узлы-маркеры найденных
  целей в `SceneView.markers` и удерживающие их твины в
  `HiddenObjectPhase._draw_found_marker`, либо твины частей пазла в
  `JigsawPiece.send_to_tray`. На геймплей не влияет, но разобраться нужно в M2 —
  запустить с `--verbose` и посмотреть, какие именно объекты остаются.

**Найдено и починено на этом этапе:**
- `PlayerState._set` перекрывал виртуальный `Object._set` → переименован в `_write`;
- `AutoplayDriver` как RefCounted освобождался сразу после вызова, корутина
  не возобновлялась → ссылка удерживается в `Boot`;
- `ShopScene._update_timer` вызывал `call_deferred("_rebuild_tasks")`, который
  снова вызывал `_update_timer` → бесконечная очередь deferred внутри одного
  кадра и полное зависание. Перестроение теперь только по
  `EventBus.cooldown_finished` + флаг `_rebuilding`.
